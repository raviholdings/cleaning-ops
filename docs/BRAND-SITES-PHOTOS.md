# 브랜드 사이트 사진 — 로컬 전용

브랜드 사이트 5개(드림컴뚜러·썬더배관·비버배관·싹쓰리배관·하수구도사)의 사진은
**git 에 넣지 않는다.** 청소 이미지(`apps/cleaning-ravi/public/cleaning/`)와 같은 방침이다 —
합쳐서 150MB 라 커밋하면 저장소만 무거워지고, 배포는 어차피 git 을 거치지 않는다.

## 어디에 있나

| 폴더 | 크기 | 무엇 |
|---|---|---|
| `output/field-photos/` | 50장 | 현장 사진. 10섹션 × 5장 |
| `output/작업사례_50장_WEBP/` | 50장 | 작업사례. 12묶음, 단계 순서(문제확인→…→작업완료) |
| `output/개별사용_작업이미지_50장_WEBP/` | 50장 | 낱장으로 쓰는 작업 사진 |
| `output/hero-concepts/` | — | 홈 히어로 배경 |
| `assets/branding/<브랜드>/` | 5폴더 | 로고·파비콘 원본 |
| `apps/brand-static/<키>-template/assets/img/` | — | 위 원본에서 만든 굽기용 사본 |

## 사진이 없으면

빌더가 멈춘다. 일부러 그렇게 해 뒀다 — 깨진 이미지가 3,000장에 박히는 것보다 낫다.

```
Error: 이미지가 없습니다: assets/img/dream-01.webp
Error: 브랜드 자산이 없습니다: assets/img/logo-mark.png
```

다른 기계에서 구우려면 `output/` 과 `assets/branding/` 을 그대로 복사한 뒤,
아래 배치를 다시 만들어야 한다.

## 어떻게 배치돼 있나

사이트마다 사진이 달라야 한다 — 같은 사진이 다섯 곳에 걸리면 한 회사로 보인다.

| 종류 | 파일명 | 사이트당 | 사이트끼리 겹침 |
|---|---|---|---|
| 현장 | `<키>-01.webp` ~ `-10.webp` | 10장 | 0장 |
| 개별사용 | `<키>-i01.webp` ~ `-i12.webp` | 12장 | 0장 |
| 사례 | `case-01-01.webp` … | 50장 | **50장 (공용)** |
| 히어로 | `<키>-hero.webp` | 1장 | 0장 |
| 로고 | `logo-mark.png` `logo.png` `favicon.png` `favicon.ico` | 4장 | 0장 |

현장·개별사용은 섹션마다 다른 컷을 사이트에 하나씩 배정해 갈랐다.
사례 50장만 다섯이 함께 쓴다 (운영자 확정 2026-08-31).

## 풀이 둘로 나뉘어 있다

`data/brands/<키>.json` 의 `images` 를 보면 된다.

```
images.pool    현장 + 개별사용 = 22장   지역·서비스·홈에서 3장씩 돌려 쓴다
images.cases   사례 50장                작업사례 페이지에서만 쓴다
```

**섞으면 안 된다.** 사례 사진은 단계 컷이라 지역 페이지에 한 장씩 떼어 놓으면
「변기 재설치 후 배수 시험」 같은 사진이 문맥 없이 뜬다. 실제로 그렇게 나갔다가 갈랐다.

## 알아 둘 것

`output/작업사례_50장_WEBP/README.txt` 에 이미지 제작처가 붙여 놓은 문구가 있다.

> 이미지는 AI로 생성된 홍보용 예시 이미지이며,
> 실제 고객 현장 촬영본으로 표시해서는 안 됩니다.

운영자는 실제 현장이라고 확인했고 그대로 작업사례에 쓰고 있다 (2026-08-31).
다만 날짜·고객 이름·동호수·연락처·금액·후기는 적지 않았고, 지역은 시·군·구까지만이다.
